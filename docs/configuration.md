# Configuration, Executors & Snowflake IDs

## `Env` Configuration Model

`Env` is a Pydantic `BaseModel` passed to `TaskRunner(instance_id=0, config=Env(...))`.

| Field | Type | Default | Constraints | Description |
| --- | --- | --- | --- | --- |
| `MERCURY_SYNC_EXECUTOR_TYPE` | `Literal["thread", "process", "none"]` | `"process"` | — | Execution backend for synchronous callables. |
| `MERCURY_SYNC_TASK_RUNNER_MAX_THREADS` | `StrictInt` | `os.cpu_count() or 1` | `>= 1` | Max worker pool size and semaphore concurrency limit for sync callables. |
| `MERCURY_SYNC_CLEANUP_INTERVAL` | `StrictStr` | `"1s"` | Valid `TimeParser` duration | Delay between background retention cleanup sweeps. |
| `MERCURY_SYNC_LOG_LEVEL` | `StrictStr` | `"info"` | — | Log level setting. |
| `MERCURY_SYNC_MAX_RUNNING_WORKFLOWS` | `StrictInt` | `1` | `>= 1` | Max concurrent workflows metadata setting. |
| `MERCURY_SYNC_MAX_PENDING_WORKFLOWS` | `StrictInt` | `100` | `>= 0` | Max pending workflows metadata setting. |
| `MERCURY_SYNC_CONTEXT_POLL_RATE` | `StrictStr` | `"0.1s"` | — | Context poll interval setting. |
| `MERCURY_SYNC_SHUTDOWN_POLL_RATE` | `StrictStr` | `"0.1s"` | — | Shutdown poll interval setting. |
| `MERCURY_SYNC_DUPLICATE_JOB_POLICY` | `Literal["reject", "replace"]` | `"replace"` | — | Duplicate job policy setting. |
| `MERCURY_SYNC_CHECKPOINT_DB_PATH` | `Optional[StrictStr]` | `None` | — | Optional SQLite file path for durable runner-managed checkpoints (`SQLiteCheckpointStore`). |

`Env.types_map()` returns a mapping of environment variable names to their parser callables (`str` or `int`).

## Choosing an Executor

`MERCURY_SYNC_EXECUTOR_TYPE` only affects **synchronous** Python callables passed to `runner.run()`. Async functions always run on the event loop, and shell commands always run via `asyncio.create_subprocess_*`.

| Executor Type | Underlying Pool | Best For | Notes |
| --- | --- | --- | --- |
| `"process"` (default) | `ProcessPoolExecutor` | CPU-bound Python functions | Bypasses the GIL. Functions and arguments must be picklable. |
| `"thread"` | `ThreadPoolExecutor` | Blocking I/O (HTTP, Docker SDK, DB drivers, file I/O) | Shares memory; works with bound methods, closures, and client objects. |
| `"none"` | Event loop default `ThreadPoolExecutor` | Async-only or shell-only workloads, lightweight apps | Avoids allocating a dedicated executor owned by `TaskRunner`. |

## Signal Handling

On POSIX platforms when running in the main thread, `TaskRunner` registers lightweight weakref-backed `SIGINT` and `SIGTERM` handlers on the active event loop so executors shut down promptly on interruption before restoring and re-raising the signal.

- Handlers are automatically removed and original OS handlers restored when the last active `TaskRunner` on a loop shuts down, aborts, or is garbage-collected.
- `TaskRunner` never touches `SIGHUP` or signals configured as `SIG_IGN`.
- Multiple `TaskRunner` instances can safely coexist on the same event loop.

## Snowflake IDs

Every `Task` (`task.task_id`) and `Run` (`run.run_id`) receives a 64-bit Snowflake ID generated by `SnowflakeGenerator`:

```text
[ 41-bit timestamp (ms) ][ 10-bit instance (0..1023) ][ 12-bit sequence (0..4095) ]
```

- Pass a distinct `instance_id` (`0`–`1023`) to `TaskRunner(instance_id=...)` when running multiple worker processes or hosts so IDs remain globally unique.
- `SnowflakeGenerator` is thread-safe, strictly monotonic, resilient to backward wall-clock skew and >4,096 IDs/ms bursts, and implements the Python iterator protocol (`next(gen)`).
- Use `Snowflake.parse(run_id, epoch=0)` to inspect the embedded `timestamp`, `instance`, `seq`, and `datetime`, or `SnowflakeGenerator.from_snowflake(sf)` to resume a generator from an existing ID.
